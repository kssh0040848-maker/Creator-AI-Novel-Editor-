检查日期：2026-11-02。检查对象：本地网页、前端请求模块、本地 Node.js 代理、上下文组装、流式正文解析。

## v0.4 新增调用与检查

- 新手模式「直接整理」为本地映射；「让 AI 帮我完善」使用真实生成接口，六问进入消息，最大输出 2,048 tokens；无有效完整 JSON 则不应用。
- 「AI 总结本章进度」使用相同接口，完整本章按容量分段，串行携带前一段摘要，单次输出上限 1,536 tokens；取消、截断或失败不创建章节。
- 章节切换、前情手改、确认摘要和创建章节都是本地操作；前章摘要进入后续续写的 system 消息，并可触发世界书。
- GET /models 现在保留有效的 context_window、max_output_tokens 元数据；容量按连接地址和模型匹配，未知容量提示保守假定。
- v0.4 测试运行器共 30 项通过；新增两种生成用途都经过前端 → 本地 HTTP 代理 → 模拟上游的请求验证。没有真实账号实测。

以下为 v0.3.1 的既有检查记录，v0.4 继续保留并运行这些检查。

## 结论与证据范围

已完成源码核查、前端请求模块 → 真实本地 HTTP 服务 → 可控模拟上游的联调，以及浏览器界面检查。测试运行器报告 24 项通过，包含 11 项新增调用检查、1 项父测试和原有 12 项测试。

没有发现真实模式失败后偷偷切换演示文案的路径。续写所需的前情、写作要求、命中设定和参数均进入发送载荷；错误会返回界面，停止会取消本地代理的上游请求。

本次没有取得或使用用户电脑中的 API Key，没有向 DeepSeek 发起真实付费生成。模拟上游成功不能证明用户账户余额、服务商权限、当前网络或实际模型效果；请使用新增「试写验证」完成本机检查。供应商对已产生用量如何计费，以实际账单为准。

## 功能与调用关系

| 功能 | 是否请求 DeepSeek | 具体行为与检查结果 |
| --- | --- | --- |
| 真实模式「继续写作」 | 是 | POST `/chat/completions`，Bearer 鉴权，流式读取正文；空白故事也能按设定请求开头 |
| 「试写验证」 | 是 | 用当前地址、模型和 Key 请求测试短句；输出上限 64 tokens；展示正文、返回模型、请求 ID 和可用的用量；不写入作品 |
| 「测试连接」 | 只读接口 | GET `/models`；没有发起文本生成，不能据此认定续写成功 |
| 前情与人物 | 随下一次续写发送 | 进入 system 消息；字段编辑本身不产生模型请求 |
| 这一段怎么写 | 随下一次续写发送 | 进入 system 消息的写作要求；并非单独的改写按钮 |
| 世界设定 | 条件满足时发送 | 词条启用、内容非空、关键词命中最近正文时加入；未命中或禁用不会发送 |
| 输出上限、创意程度 | 随下一次续写发送 | 对应 `max_tokens`、`temperature`；DeepSeek 预设关闭思考 |
| 最近正文范围 | 本地裁剪后发送 | 只发送设定范围内的最近正文；标题用于管理，不加入提示词 |
| 查看本次发送的上下文 | 否 | 本地预览，与续写使用同一个组装函数 |
| 停止续写 | 取消现有请求 | 传播 AbortSignal；保留已收到内容；不会自动重发 |
| 撤销、重做 | 否 | 在本地恢复文字和来源色；不会重新生成或额外计费 |
| 新建、搜索、编辑、自动保存 | 否 | 浏览器 IndexedDB 保存；不上传作品到本应用云端 |
| 导入、导出、备份 | 否 | TXT/JSON 文件操作；不会触发模型生成 |
| 字号、专注、侧栏、自动跟随 | 否 | 页面显示和滚动行为 |
| 慧慧点击互动 | 否 | 本地固定灵感短句和动画；当前不是 AI 聊天功能 |
| 演示续写 | 否 | 插入固定示例，界面明确标识演示；不能用于评价模型质量 |
| 保存并启用连接 | 否 | 本地保存地址和模型；Key 只放当前页面内存；不自动生成 |

“设定已发送”不保证模型每次都遵守要求，最终文本质量仍需实际故事评估。

## 本次发现并修复

1. **刷新后的状态容易误判**：以前仍显示「真实 API」；现在密钥清空时显示「待填密钥」，点击续写会打开连接设置。
2. **模型列表可用不等于生成可用**：保留「测试连接」并明确范围，新增独立「试写验证」及费用说明。
3. **只有空格的返回可能被视作完成**：现在空正文和仅思考内容均报错，只有空白的追加内容不会保留为成功续写。
4. **流式错误提示过于笼统**：保留上游错误原因；提前断流、格式不兼容分别提示；已收到的正文保留。
5. **浏览器本地连接失败缺少指引**：替换原始 `Failed to fetch` 为检查启动窗口与本地地址的提示。
6. **缺少可见的返回证据**：续写结束显示返回模型与字数；悬停结果摘要可见请求 ID（服务商有提供时）。试写验证直接展示完整回执。
7. **解析出错后的流继续读取风险**：解析失败时取消 reader，结束读取并把取消传递到本地代理。

## 新增检查覆盖

- `/models` 只发送 GET，没有生成请求。
- 前情、写作要求、命中世界设定、模型、长度、温度实际出现在上游请求中；禁用、未命中设定和被裁剪的旧正文不发送。
- API Key 位于鉴权头，不写入消息载荷；显示偏好不会混进模型请求。
- 试写验证输出上限 64 tokens，解析正文、返回模型、请求 ID 和用量。
- 401、402、429 显式失败且只请求一次，不自动重试或回退到演示。
- 空正文、仅思考返回、流式中途断开、上游错误流均不会被当作成功。
- 停止信号到达代理上游请求；本地服务不可达有明确操作提示。
- 浏览器实际检查：新增入口与费用说明可见；仅以占位字符串保存本地配置后刷新，显示「待填密钥」；点击续写打开连接设置。没有向供应商发送占位 Key。

## 在你的电脑上完成真实验证

1. 启动 v0.3.1，打开 `http://127.0.0.1:4317`。
2. 「模型连接」选择 DeepSeek 官方，填写自己的 Key，使用 `https://api.deepseek.com` 与 `deepseek-flash`。
3. 点「试写验证」。会使用账户额度，输出上限 64 tokens。
4. 确认看到了实际短句，记录返回模型、请求 ID、用量；再点「保存并启用」。
5. 在故事中填一个明确人物特征、一个写作要求和一个可触发词条，预览上下文后续写，核对输出效果。
6. 若失败，提供状态提示或回执截图并遮住 Key。不要把完整 Key 发到聊天。
