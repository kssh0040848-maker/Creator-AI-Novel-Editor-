# 创作家 v0.4.2：交互与文风设计说明

更新：2026-11-03。适用 Windows 与 Mac 本地网页版本。

## 这次改了什么

1. 界面指引增至九步，独立说明「前情与人物」「这一段怎么写」「世界设定」。每步只说怎么用，右下角保留「跳过指引」。旧用户可从书架重新打开。
2. 新手模式移到书架，在「开始一个新故事」上方。两个按钮同宽、同等层级，分别用于问答建故事和直接打开空白页。
3. 第一题加入「童话故事」。第二题为「主角是谁？」，提示填写名字、身份、性格特质，不要求弱点。
4. 第四题改成「主角将要面临的困难是什么？」。
5. 第六题改成「你希望是什么文风？」，提供六种文风，支持补充要求或完全自填。
6. 问题用大标题，提示独立显示为「怎么答」。选项有边框、底色和选中勾号；「给我一个例子」始终显示为按钮，再点可换例子。底部上一题／下一题固定，内容区独立滚动。
7. 保留黑色、紫色、薄荷绿主题和慧慧；统一其他常用按钮的可点击外观。

## 文风如何影响生成

| 选择 | 具体语言要求 |
| --- | --- |
| 网络小说 | 现代白话、短段落、行动与对话推进、明确的目标和阻力 |
| 言情散文 | 具体感官细节、情绪寄托于动作、克制比喻、抒情后回到行动 |
| 文言文 | 浅近文言、短句、省略、现代标点、不附白话译文、不擅改时代背景 |
| 朴素写实 | 准确常用词、生活化对白、少修饰和评判、通过细节表达情绪 |
| 轻松幽默 | 轻快口语、处境反差、自然笑点、保留人物动机 |
| 童话叙述 | 易懂词语、短句、具体意象、清楚因果、温柔叙述 |

每项都有一段为本项目新写的短示例。示例用于比较语言，不属于故事剧情；提示词明确要求不复用示例人物和情节。

实际发送内容包括「具体文风规则＋短示例＋用户补充＋连续性与输出要求」，进入续写请求的 system 消息。模型按每次请求接收这些内容，不依赖它记住上一次的选择。用户补充优先于默认规则；明确选择新文风时，不会被旧正文的默认风格要求覆盖。

本地直接整理会原样生成作者注。选择 AI 完善时，模型收到同样的约束；返回后应用再次附上原选项的规则，避免整理过程中省略。核对页可编辑，创建后也能在右侧「这一段怎么写」修改。新章节与 JSON 备份沿用同一份作者注。

自定义例子：

> 文言文
> 补充要求：第一人称，句子短一些，人物对话多一点。

也可以完全自行描述：

> 书信体，用第二人称，像写给远方朋友的信。用日常词语，少用比喻。

## 调研依据与本项目的取舍

- [GOV.UK：Question pages](https://design-system.service.gov.uk/patterns/question-pages/)：问题应成为页面的主要标题；提示要简短、贴近回答任务。对应为一题一屏、明显的标题与提示层级。
- [Nielsen Norman Group：Flat UI Elements Attract Less Attention and Cause Uncertainty](https://www.nngroup.com/articles/flat-ui-less-attention-cause-uncertainty/)：可点击线索弱的界面会增加寻找操作的负担。对应为按钮常态就显示底色与边框，并补齐悬停、键盘焦点、按下和选中状态。
- [Anthropic：Prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)：明确要求、区分说明与示例，并用相关示例引导语气与结构。
- [Google：Prompt design strategies](https://ai.google.dev/gemini-api/docs/prompting-strategies)：示例能帮助表达措辞与输出形式，具体效果需要迭代验证。
- [DeepSeek：Chat Completions API](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)：支持 system 消息；temperature 控制采样随机性。它不能替代对文风的具体描述，因此本次选择文风不会自动改变生成参数。

这些资料支撑交互和提示词的设计方法，不构成 DeepSeek 对中文小说文风表现的保证。六类规则与示例是本项目的设计方案；没有复制其他小说产品的界面素材或作者原文。

## 建议你这次重点试什么

同一个故事开头，用相同模型、相同生成参数，分别试「网络小说」「言情散文」「文言文」。每种生成两段即可，主要看：

1. 用词和句式是否明显不同，是否符合你选的风格。
2. 主角、世界规则、已发生剧情是否保持一致。
3. 补充的第一人称、短句等要求是否生效。
4. 是否出现示例中的阿宁或旧钥匙；如果发生，就是示例串入剧情，需要继续调提示词。

演示模式使用固定文本，不适合评价文风。右侧「查看本次发送的上下文」可核对真实请求将携带的要求。

## 更新与保留故事

先在旧版「备份全部故事」，关闭旧启动窗口，解压新版。用原来的浏览器继续打开 `http://127.0.0.1:4317`。本次没有改变存档数据库，也不会自动改写你已有作品的作者注。换浏览器或设备时导入 JSON 备份。
