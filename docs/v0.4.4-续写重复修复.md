# v0.4.4：手动修改后的续写衔接

日期：2026-11-03。本次发布 Windows 更新包与单文件原型。

## 问题与原因

用户在正文末尾补写或修改一句，再点击继续写作时，模型可能先重写这句再继续。此前界面直接追加每一段模型输出，缺少衔接重复检查，因此原句与模型重写的句子会并排出现。

检查确认：编辑事件即时更新正文，生成前提交编辑历史，上下文按当前正文重新构建。此次修复针对模型输出开头回声，不声称能够排除所有形式的语义重复。

## 修复行为

1. 提示词明确当前正文包含作者最新修改；从最后一个字符继续，末句不完整时补齐剩余部分，不重新开始该句。
2. 只在本次输出开头比较与原文末尾的重合。遇到明确重复时略去这部分，再追加后续内容；原文及颜色不动。
3. 支持跨多次流式事件的匹配，不要求重复句一次性返回。
4. 已收到但尚未确认重复的文字在停止、连接中断或报错时保留。
5. 正文内部的重复表达不做全文清理；总结、设定 JSON、试写验证不经过这个过滤器。
6. 仅返回重复内容时不制造新增正文或撤销记录，给出明确提示，不自动重试付费请求。

比较范围：原文最后 4,096 个 Unicode 字符；忽略空格、换行和缩进，保留标点、大小写和实际措辞差异。候选必须包含至少 8 个文字或数字字符，避免误删人物名、短词。待定缓冲有 16,384 字符上限，达到上限后保留未判定文字。

这属于明确重合保护，不进行语义相似度删除。近义改写、极短重复和超出比较范围的重复仍可能出现。用户希望保留的长句首尾重复也可能被视为回声；原文不会被删除，必要时可手动补写。

## 使用方式

无需额外设置，真实模型续写自动启用。旧版已生成的重复句不会被自动改动，请手动删除一次，或用撤销回到续写前。当前按钮始终从本章末尾续写；修改正文中间不会自动覆盖后面的文字。

- 47 项自动化检查全部通过。
- 新增手动修改即时上下文、跨任意分块的重复前缀、空白差异、多候选重合、正常重复保留、仅重复输出、中途停止、流断开、再次续写、颜色及撤销重做检查。
- 前端生成函数通过本地 HTTP 代理接入可控模拟上游，确认只发出一次请求，最新正文被发送，返回的重复前缀未进入新增正文。
