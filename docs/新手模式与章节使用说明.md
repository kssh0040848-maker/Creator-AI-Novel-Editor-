# 创作家 v0.4.2 · 新手模式与章节使用说明

更新日期：2026-11-03。适用 Windows 与 Mac 本地版。

## 一、第一次写小说：六问就能开始

在左侧书架点「新手模式」，它位于「开始一个新故事」上方。每次只回答一题，可选答案、自己填写或点「给我一个例子」。回答自动保存在当前浏览器。

| 问题 | 帮你确定什么 | 填入的位置 |
| --- | --- | --- |
| 1. 你想写哪种故事？ | 故事方向 | 故事记忆 |
| 2. 主角是谁？ | 名字、身份、性格特质 | 故事记忆 + 人物世界书 |
| 3. 主角想做到什么？ | 主线目标 | 故事记忆 |
| 4. 主角将要面临的困难是什么？ | 冲突与选择 | 故事记忆 |
| 5. 发生在哪里，有何规则？ | 世界背景 | 故事记忆 + 世界书 |
| 6. 你希望是什么文风？ | 用词、句式、节奏、情绪与自定义要求 | 作者注 |

六问的目标是形成能动笔的基础设定；长篇的复杂人物关系和支线可以在写作中继续补充。

第六题后进入核对页，名称、故事记忆、作者注、每个世界书词条与关键词都能修改。

- 「按回答重新整理」：本地整理，不调用模型，不产生模型费用。
- 「让 AI 帮我完善」：使用当前模型连接，1 次真实生成请求，输出上限 2,048 tokens。需要先填写 Key；AI 可能补充创意，需要核对。
- 「创建故事并填入」：创建一部新故事。设定映射到右侧的「前情与人物」「这一段怎么写」「世界设定」。原有作品保留。
- AI 失败、停止、格式不完整时，不应用半成品。原回答和当前草案保留。关闭或刷新会丢失尚未应用的核对页修改，但六题回答会保留。

## 二、看懂两种“上限”

### 模型上下文容量

截至 2026-11-02，DeepSeek 官方 deepseek-flash 与 deepseek-v4-pro 的上下文窗口为 1,048,576 tokens（1M）；这个容量包含输入与输出，不是中文的字数，也不保证所有细节都被稳定使用。

应用先使用手动设置；没有手动设置时，优先使用「测试连接」返回的模型容量，再用已核对的官方预设。其他模型识别不到时，明确提示暂按 8,192 tokens 预警，可在「生成设置」里按供应商规格填写。更换模型连接会清除旧的手动容量。

### 本次正文读取范围

默认只带入最近 12,000 个正文字符，可以选择 4,000 / 12,000 / 24,000 / 48,000。故事记忆、作者注、前章摘要和已触发世界书另行带入。本地服务一次请求仍限制在 90,000 个消息字符以内，并没有开放整段 1M 输入。

正文越长，较早部分可能先超出这个读取范围，远早于模型容量耗尽。界面会显示本章字符数、本次带入数、遗漏的较早字符数，以及包含输出预留的 token 估算。

Token 值是按字符类型保守估算，不是官方 tokenizer 的精确计算。应用保留约 10% 容量余量，实际用量以服务商回执为准。续写时若容量不足，会减少本次最近正文范围并提示；基础设定本身过大则阻止发送，要求调整。

## 三、到了边界，由你决定

达到所选正文读取范围的 85%，或预估请求达到模型容量的 80%，或消息字符接近本地请求限制时，再次续写会显示选择：

- 「继续本章」：按界面显示的上下文范围继续写；原文保留。较早剧情需要记忆或摘要补足。
- 「总结并新建章节」：打开摘要核对窗口。
- 「返回编辑」：修改设定、读取范围或容量。

同一进度区间确认继续后不会每次弹窗；新增约 2,000 字符或用量区间/读取设置改变后会重新评估。硬性超限时不能直接继续发出超限请求。

## 四、总结进度，开始下一章

也可以随时点击正文上方「总结 / 新建章节」。当前需处于最后一章，暂不创建平行分支。

1. 查看完整本章有多少字符、需要几次总结请求。
2. 点击「AI 总结本章进度」，或自己填写摘要。
3. 核对人物状态、已发生事件、时间地点、关键物品、未解伏笔、最后一幕。
4. 编辑下一章标题，勾选「我已核对摘要，确认用于下一章」。
5. 点击「确认摘要并创建下一章」。

总结读取本章完整正文与之前的摘要；长章按容量分段，逐段合并前情。每段输出上限 1,536 tokens，分段次数在开始前显示，真实调用使用账户额度。摘要压缩可能遗漏细节，确认前应与原文核对。

取消、网络错误、空返回或截断时，不自动创建章节，也不改动原文。分段请求已经产生的用量可能计费。失败后重试会从头总结。

新章正文为空，带入你确认的前情摘要并承接上一章；共享故事记忆、作者注和世界书。世界书可以由近期正文或前章摘要中的关键词触发。

## 五、章节与备份

- 正文上方的章节下拉菜单可切换各章，旁边可改本章名称。
- 每章有独立的正文、来源颜色、撤销和重做记录。
- 旧故事自动作为第 1 章；旧版 JSON 仍可导入。
- 修改前序章节后，后续章会提示核对摘要；请按顺序核对，并点「我已核对这份摘要」。不会自动改写后续摘要。
- 导出正文 TXT 包含全部章节；JSON 备份包含全部章节、设定、摘要和编辑历史。多章备份请用 v0.4 或更新版本导入。
- 当前每部最多 100 章，每章最多 20 万字符；导入文件限制仍为 20 MB。请定期备份。

## 六、验证范围

自动化测试运行器报告 30 项通过（含原有父测试），包括六问映射、关键词触发、章节切换与历史隔离、JSON 往返、读取范围与容量预算、完整分段总结、停止与错误不改原文，以及前端 → 本地 HTTP 代理 → 模拟模型的两条新增调用路径。

桌面浏览器已验证：六问 → 核对 → 创建 → 三类设定填入；超出读取范围 → 继续本章；手动摘要确认 → 新建章节；刷新保留章节；切回旧章恢复正文与历史；上下文预览包含摘要及命中词条。

未使用真实 API Key 发起付费请求。实际模型整理质量、中文摘要完整性及本机网络需要在你的电脑验证。小米 K80 的键盘与触摸交互还需实机体验。
